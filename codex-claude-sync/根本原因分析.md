# 根本原因分析

经过深入调查，我发现了关键问题：

## 问题根源

**Claude Code 和 Codex 使用的是不同的技能加载机制**

### Codex 的技能系统
- 自动扫描 `.codex/skills/` 和 `.agents/skills/` 目录
- 每个技能是一个目录，包含 `SKILL.md`
- `config.toml` 中的 `[[skills.config]]` 只用于**禁用**特定技能
- 所有技能默认启用

### Claude Code 的技能系统（推测）
根据文件系统证据：
1. **项目级 skills-lock.json** 存在于项目根目录
2. Skills 目录存在于全局 `.claude/skills/`
3. 但 UI 只显示 1 个技能

## 核心发现

查看 `D:/WILL/AGENT/agent/skills-lock.json`：
```json
{
  "yosef-server": "USER_SKILL"
}
```

**这是关键！** 这个文件只包含 1 个技能：`yosef-server`

## 推测的工作机制

Claude Code 可能使用 **项目级技能注册**：
1. 技能文件存放在全局 `.claude/skills/`
2. 但需要在 **项目级** 通过某种方式激活
3. `skills-lock.json` 可能记录了已激活的技能
4. Settings → Skills 页面显示的是 **当前项目激活的技能**

## 验证方法

### 方法 1: 更新 skills-lock.json

尝试将所有技能添加到项目的 `skills-lock.json`：

```json
{
  "apex-strategy-report": "USER_SKILL",
  "ask-matt": "USER_SKILL",
  "asr": "USER_SKILL",
  "batch-grill-me": "USER_SKILL",
  ...所有 56 个技能
}
```

### 方法 2: 删除 skills-lock.json

删除这个文件，让 Claude Code 重新扫描和注册。

### 方法 3: 使用 Claude Code UI

在 Settings → Skills 页面可能有"添加技能"或"扫描技能"的功能。

## 关键问题

**Skills 是全局的还是项目级的？**

根据观察：
- 文件存放：全局 (`.claude/skills/`)
- 激活/注册：项目级 (`项目/skills-lock.json`)

这意味着：
- 技能文件已经正确复制
- 但需要在每个项目中"激活"它们
- 或者需要某种全局激活机制
